## Conventions (all phases)

- **Stack:** .NET 10, C#. `System.Text.Json` (`System.Text.Json.Nodes`) for JSON. **xUnit**
  for tests (free — do NOT add FluentAssertions; v8 is commercial). No new NuGet deps unless
  a phase explicitly needs one.
- **Layout:** `ClaudeExplorer.slnx` (note: .NET 10 emits the new `.slnx` format) ·
  `src/ClaudeExplorer.Core` · `src/ClaudeExplorer.App` (UI, phase 7+) ·
  `tests/ClaudeExplorer.Core.Tests`.
- **Testability seams:** Core depends on abstractions so every engine runs against
  fixtures and never touches the real machine: `IFileSystem` (exists; has FileExists,
  ReadAllText, DirectoryExists, GetDirectories, GetFiles). Add `IProcessRunner` (phase 3),
  `IPathResolver` (phase 3), catalog fetch seam (phase 4) the same way, each with a
  `Physical*` impl in Core and an in-memory fake in tests.
- **TDD + a commit per task.** Names matched **case-sensitively (ordinal)** by design
  (commands, skills, env keys) — consistent across the codebase.
- **Paths use forward slashes** in code for determinism; .NET accepts `/` on Windows.

## Precedence (authoritative — used by phase 1; verify against real Claude when in doubt)

Settings precedence, **highest wins**:
`Enterprise/managed (3) > Local .claude/settings.local.json (2) > Project .claude/settings.json (1) > User ~/.claude/settings.json (0)`
(CLI args sit above Local at runtime but aren't modeled — this tool reads files.)

Per-key merge semantics:
- **Scalars** (`model`, `outputStyle`, `statusLine`, `permissions.defaultMode`, each
  `env.*`): highest-precedence scope wins; *conflict* = >1 distinct contributed value.
- **Permission lists** (`permissions.allow|deny|ask`): **union** (dedup, precedence order).
- **Hooks** (`hooks.<Event>`): **array concat** across scopes.

Artifact (command/skill/subagent) source precedence for shadowing:
`Project (2) > User (1) > Plugin (0)`; same-precedence ties broken by plugin name then path.

# Phase scope outlines (3–8)

Each is Core-only & TDD unless noted. Expand into a full plan (exact files + complete
code + tests, like phases 1–2) before executing.

## Phase 3 — Dependency health
**Goal:** From discovered config, extract the executables it depends on and verify they're
available — *safely* (never run untrusted config).
**Deliverables:**
- Seams: `IProcessRunner` (run an allowlisted `--version` probe → exit/stdout) + `Physical`
  impl + fake; `IPathResolver` (resolve exe on PATH, like which/where) + impl + fake.
- Executable extraction from: settings `hooks.*` command strings (Phase 1), and MCP server
  `command`+`args`. **Note:** MCP server definitions aren't parsed yet — either add a
  minimal `.mcp.json`/settings `mcpServers` command reader here, or sequence a minimal MCP
  reader first. Recognize wrappers: `npx <pkg>`, `uvx <pkg>`, `uv run`, `python -m`,
  `docker run`, `podman …`, plain binaries.
- Allowlist of safe runtimes for `--version`: node, npm, npx, pnpm, yarn, bun, deno, uv,
  uvx, python, python3, docker, podman, git, claude.
- `DependencyChecker` → per ref: resolve on PATH + allowlisted `--version` only; classify
  Found / Missing / Unverifiable (present but not allowlisted-probeable). Model:
  `DependencyRef(name, raw, referencedBy[])`, `DependencyStatus(kind, version?, path?)`,
  `DependencyReport`. Façade `DependencyHealthService`.
**Hard rule:** allowlist + `--version` only; never execute the actual hook/MCP/arbitrary
binary. **Tests:** wrapper extraction (npx/uvx/docker), allowlist enforcement, missing exe,
fake runner/resolver. **Depends:** Phase 1 (+ MCP reader).

## Phase 4 — Catalog + user-added sources (trust)
**Goal:** Read installable items from Claude marketplaces + user-added sources; normalize
with trust. **Metadata-only — nothing fetched/run until install.**
**Deliverables:**
- Seam: `ICatalogFetcher`/`IHttpClient` (no real network in tests) + fake.
- `CatalogSource(kind: ClaudeMarketplace|Url|GitHub, trust: Verified|Community, name, location)`;
  source detector (URL vs `owner/repo` vs github.com URL vs marketplace); manifest
  reader/normalizer → `CatalogItem(name, type, summary, source, trust, stats?)`; `CatalogService`.
- Trust: official Anthropic marketplace = Verified; user-added = Community (clearly flagged).
**Tests:** source-type detection, manifest parse, trust assignment, dedupe, fake fetcher.
**Depends:** Phase 2 concepts.

## Phase 5 — Project-fit recommendations
**Goal:** Locally analyze a project into signals → match catalog − installed → annotate
with dep health → why + evidence. **Local-only — never upload project contents.**
**Deliverables:** pluggable `ISignalDetector`s (language/framework/test-runner/DB/
issue-tracker/commit-pattern from fixture project trees) → `ProjectSignals`; matcher rules
(signal → catalog item w/ reason + evidence file refs + confidence); exclude installed
(Phase 2); annotate with dep health (Phase 3); `RecommendationService`.
**Rule:** every recommendation must carry why + evidence (linkable to source file).
**Tests:** signal detection from fixtures, matcher reasons/evidence, installed excluded,
dep-health annotation. **Depends:** Phases 2, 3, 4.

## Phase 6 — Safe-mutation
**Goal:** Apply edits/installs safely & reversibly.
**Deliverables:** `ScopeTarget` resolution (edit winner vs override at Project/Local);
JSON-schema + frontmatter validation; diff generator; `IBackupStore` (timestamped snapshots)
+ fake; scope-aware `ChangeLog` (entries grouped by scope); `Mutator` — apply via direct
file write (config) or `claude` CLI via `IProcessRunner` (installs); one-click undo/restore
(uninstall for installs).
**Hard contract (all required):** scope-target picker, diff preview, schema validation,
auto backup, undo/restore, reviewable scope-aware change log.
**Tests:** scope-target resolution, backup+undo round-trip, validation blocks bad JSON,
change-log entries, diff correctness — all against fixtures/temp, no real machine writes.
**Depends:** Phase 1, `IProcessRunner`.

## Phase 7 — Blueprint UI shell + Dashboard
**Goal:** The desktop app shell in the chosen **Blueprint** aesthetic.
**Deliverables:** `src/ClaudeExplorer.App` (Photino.Blazor), MVVM (observable ViewModels +
logic-light Blazor views, DI to Core), Blueprint theme/tokens (from `ux-explorations/` —
graph-paper grid, corner-tick panels, Archivo + Spline Sans Mono, electric-blue accent),
reusable component library (corner-tick panel, source card, dark code/diff viewer, type/
trust badges, scope tags, confidence bar), app chrome (left rail, top bar w/ project
selector + refresh), and the **Dashboard** (health, counts, conflicts, recent changes).
**Notes:** bundle fonts (no CDN at runtime); Blueprint needs real custom CSS over MudBlazor
(budgeted). Prototypes to match: `ux-explorations/03-blueprint.html` (+ `01`,`02` for the
rejected directions). **Tests:** ViewModel logic (no rendering); manual run via `/run`.
**Depends:** Phase 1 (+ 2, 3 for dashboard counts).

## Phase 8 — Per-screen UI
**Goal:** Build each screen on the shell, ViewModel-first, matching the prototypes.
**Screens (each = tested ViewModel + Blueprint view):** Effective Config precedence matrix
(`04-blueprint-effective-config.html`) → Commands & Skills browser (`05`) → Dependencies →
Marketplace Browse + Add-source + Install flow (`07`,`08`) → Recommended-for-project (`09`) →
Change Log → multi-project compare. Reuse the Phase-7 component library; each screen consumes
the matching Core engine. **Depends:** Phases 6, 7 + the relevant engine per screen.
