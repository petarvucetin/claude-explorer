# Claude Explorer — Implementation Roadmap

This decomposes the spec (`CLAUDE.md`) into a sequence of plans. Each plan produces
working, tested software on its own and is the unit of a Linear grouping.

## Build order & rationale

| # | Plan | Goal | Depends on |
|---|------|------|------------|
| 1 | **Core config engine** | Compute effective `settings.json` config with provenance, conflicts, and per-key merge semantics from fixture `.claude` dirs. Pure library, no UI. | — |
| 2 | **Artifact parsers** | Discover + categorize CLAUDE.md memory, slash commands, skills, subagents, MCP servers, plugins/marketplaces (source attribution + override/shadow resolution). | 1 |
| 3 | **Dependency health** | Extract executables from hooks/MCP/commands; safe allowlisted `--version` probing; found/missing/version report. | 2 |
| 4 | **Catalog + sources** | Read Claude marketplaces + user-added sources (URL/GitHub/`owner/repo`) with trust levels; metadata-only normalization. | 2 |
| 5 | **Recommendations** | Local project signal detection → match against catalog − installed, annotated with dep health; why + evidence. | 3, 4 |
| 6 | **Safe-mutation** | Scope-target resolution, schema validation, diff, backup, apply (CLI/file), change-log, undo. | 1 |
| 7 | **Blueprint UI shell** | Photino+Blazor+MudBlazor app, MVVM, Blueprint theme/tokens + component library, app chrome (rail/top bar/project selector), Dashboard. | 1 |
| 8+ | **Per-screen UI** | Effective Config matrix → Commands & Skills → Dependencies → Marketplace (Browse/Add-source/Install) → Recommended → Change Log → multi-project compare. | 6, 7 + the relevant engine |

Plans 2–6 are Core-only (headless, fully unit-testable). Plans 7+ are UI and consume the
engines via DI/ViewModels.

## Conventions (all plans)

- **Stack:** .NET 10, C#. `System.Text.Json` for JSON. **xUnit** for tests (free).
- **Layout:** `ClaudeExplorer.sln` · `src/ClaudeExplorer.Core` · `src/ClaudeExplorer.App`
  (UI, plan 7+) · `tests/ClaudeExplorer.Core.Tests`.
- **Testability:** Core takes an `IFileSystem` (and later `IProcessRunner`) abstraction so
  every engine is tested against in-memory fixtures and never touches the real machine.
- **TDD + frequent commits**, per task.

## Precedence (authoritative — used by plan 1)

Claude Code settings precedence, **highest wins**:
`Enterprise/managed > (CLI args, not modeled) > Local (.claude/settings.local.json) >
Project (.claude/settings.json) > User (~/.claude/settings.json)`.

Per-key merge semantics:
- **Scalars** (`model`, `outputStyle`, `statusLine`, `permissions.defaultMode`, each
  `env.*`): highest-precedence scope that defines the key wins; a *conflict* exists when
  more than one scope contributes differing values.
- **Permission lists** (`permissions.allow|deny|ask`): **union** across scopes (dedup).
- **Hooks** (`hooks.<Event>`): **array concat** across scopes.
